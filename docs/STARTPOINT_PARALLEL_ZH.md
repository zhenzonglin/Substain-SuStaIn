## 工作站执行

当前仍处于C3 crossvalidate、每折K=1已完整写盘时执行：

```bash
cd /data02/linzhenzong/Substain-SuStaIn &&
git pull --ff-only &&
.venv/bin/python scripts/switch_startpoints.py --config config/local.38.yaml --apply
```

这是立即切换入口，不等待K=2。它先核验再暂停/停止旧任务，随后后台续跑。不要额外手工kill，不要另开all任务。不加`--apply`仅预检。已切换且仍在运行时重复调用不会再次停止或启动。

## CPU和内存限额

全部参数集中在`config/startpoints30.yaml`，切换后实际执行项写入本机`config/local.38.yaml`的`startpoint_parallel`区。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `physical_core_limit` | 30 | 用Linux的socket/core拓扑选择不同物理核 |
| `logical_cpu_limit` | 60 | 选择上述物理核的SMT兄弟，限制CPU亲和性范围 |
| `workers_per_fold` | 3 | 每个活跃CV折最多3个独立起点 |
| `fit_workers` | 25 | 主模型/稳定性模型最多25个起点，同时受内存和物理核预算限制 |
| `runtime.blas_threads` | 保持1 | 每个起点为单线程数值计算，不嵌套BLAS并行 |
| `runtime.max_memory_fraction` | 保持原值 | 当前工作站原配置为可用内存的80% |

CV折数仍为10，外层请求上限保持10；内存不足时减少同时活跃的折，不减少折总数或起点总数。调度同时检查CPU亲和性、可见cgroup CPU配额、可用内存、候选张量、父进程保留的上一K链及磁盘预算。每个活跃折获得互不重叠的物理核组；其起点分别绑定单个物理核的逻辑CPU兄弟。进程池使用spawn，避免复制父进程的心跳线程和锁。起点池结束后释放子进程再进入MCMC。

30/60是资源上限，不是对操作系统总进程数的承诺。折协调器、主协调器和资源跟踪器是额外的轻量进程。按6792例C3、38维、K上限6、原内存安全倍数2、116.21GiB可用内存的本地资源模型，预期放行8折×3起点=24个计算进程；实际值由工作站启动时预检决定。此估算不是实时内存测量或工作站速度测试。主模型MCMC和每折MCMC不能通过增加起点数并行拆链，整体提速比例需实测。

## 新增起点检查点

新任务的检查点位于各折/种子目录下`startpoints/k_<K>/<批次哈希>/point_<编号>/`，每个完整起点包含`result.npz`、`complete.json`及独立进度文件。

批次身份包括数据值及布局、初始化序列和比例、完整子种子状态、阈值、算法源码、依赖版本和模型身份。只有结果原子写入且完整性回执落盘才计为完成。恢复时校验身份及哈希，完整点保持字节和mtime不变，未完成点重算；损坏的完整点拒绝覆盖。调度按原始起点索引返回结果，不使用“最快完成者”或改变并列处理，父进程官方随机流保持原样。

这是完成起点之间的恢复，不是EM轮内或MCMC链内续跑。原版本已经运行过但没有此检查点的起点不能追溯恢复。
